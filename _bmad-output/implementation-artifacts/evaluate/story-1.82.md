## Intent

**Problem:** A Bubblewrap target sees the host through `--ro-bind / /`. A read-only mount stops writes, and a `connect()` to a socket file is no write, so a process of the target can connect to `/var/run/docker.sock`, the system bus at `/run/dbus/system_bus_socket` or an agent's socket under `/tmp` and ask the host service behind it to run a job outside the sandbox. Story 1.31 hides `/run/user` only, and Story 1.63's network namespace hides the abstract sockets and leaves the socket files.

**Approach:** Each call lists the host's path-based Unix sockets when it starts and mounts an empty device file over each socket file outside the call's own grants, so a `connect()` finds no socket there and answers `ECONNREFUSED`. The list is the kernel's table of bound Unix sockets (`/proc/net/unix`), the socket files beside a listed path that was moved after it bound, and the socket files in the directories where services and sessions keep them (`/run`, `/var/run`, `/tmp`, `/var/tmp`, one directory down). The mounts go before the call's binds, so a socket in the workspace or in a private directory of the call stays connectable.

## Boundaries & Constraints

**Always:** The target's vector alone carries the mounts (`bubblewrapTargetArguments`); the probes and the evaluation layer's vector do not. A socket path goes into the vector by its real path, since Bubblewrap cannot mount over a path that goes through a link. The list is read when each call starts. A call whose Bubblewrap never started its shim while a socket it hid went away is started again over its own list without the vanished sockets, a start for each socket that went away at most. The reference states what is hidden, what stays reachable and each limit, and each sentence names the case that backs it. Any change to a Bubblewrap vector updates the byte-identity golden. No eval-quality change, no new dependency, no native build, no new Linux package.

**Never:** a mount over the call's own grants, a claim in the reference no case backs, a change to the Seatbelt profile, a registry field, a change to what the evaluation layer's vector allows.

**Decisions (build worker, owner-delegated):** the Decisions list below carries each choice with its reason and the Linux evidence.

## Linux evidence and how it ran

The host is macOS with no `bwrap`, so every Linux case ran in a container of the local image `tea-bwrap-strace` (Debian bookworm, node 24, bubblewrap 0.8.0, strace 6.1, git 2.39, a user `tester` that is not root). Docker Desktop's engine was stopped when the build began; `docker desktop restart` brought it up.

```sh
docker run --init --rm --security-opt seccomp=unconfined --security-opt apparmor=unconfined \
  --security-opt systempaths=unconfined --cap-add SYS_ADMIN --cap-add SYS_PTRACE \
  -u tester -e HOME=/home/tester -v <copy of the tree>:/work -v <worktree>/node_modules:/work/node_modules:ro \
  -w /work tea-bwrap-strace node test/test-evaluate-run.js --group=confinement
```

`--security-opt systempaths=unconfined` lets `bwrap --proc /proc` mount procfs under a user namespace, `SYS_PTRACE` lets `strace` trace, and `--init` reaps the servers a case kills (without it `the confined pipeline` and `the bridged server` fail on an unreaped child, with or without this change). A host with stand-ins for the system bus and the Docker socket served by an unprivileged user (`/run/dbus/system_bus_socket`, `/var/run/docker.sock`, a link to `/run`) ran as root first (`chmod 777 /run`) and then dropped to `tester`. The tree was copied out of the worktree for each run, with `.git` left out; that makes three checks of the `run` group about `.gitignore` fail in the container and nothing else.

**Reproduction.** On the unchanged vector (`--unshare-user --unshare-net --ro-bind / / --dev /dev --proc /proc`), a confined `node` connecting to `/run/dbus/system_bus_socket`, `/var/run/docker.sock` and `/tmp/agent.sock`, each served by another process, printed `connected` three times. The existing `the abstract socket route` case asserted `connected` for a path socket outside the grants ("Story 1.82 closes that").

**Mechanism checks.** `--ro-bind /dev/null /tmp/agent.sock` makes the connection answer `ECONNREFUSED`. The same mount over `/var/run/docker.sock`, where `/var/run` is a link to `/run`, fails: `bwrap: Can't create file at /var/run/docker.sock: No such file or directory`; the mount over `/run/docker.sock` covers both spellings, so the vector names the real path. A mount over a path that vanished fails with `bwrap: Can't create file at /tmp/gone.sock: Read-only file system` and exit 1, which is the failure the retry answers.

**Late and recreated sockets.** A socket bound under `/tmp` after the call started answered `connected` while the early one, masked, answered `ECONNREFUSED`. A masked socket unlinked and bound again at the same path answered `ECONNREFUSED` before and `connected` after, since a mount covers one file and the kernel detaches it when the file goes. Neither can be closed with a mount of a read-only `/`; both are limits the reference states.

**Landlock.** `landlock_create_ruleset` answered `ENOSYS` on this container's kernel (6.10.14, linuxkit). The access rights of the header the container ships (`/usr/include/linux/landlock.h`) are file and directory rights, `MAKE_SOCK` to create a socket file and none to connect to one.

## Decisions

1. **An empty device file over each listed socket, over the real path, before the call's binds.** Chosen because it changes only what it names (`reads elsewhere stay allowed and audited`), needs no capability and no kernel feature beyond the user namespace Bubblewrap already needs, and answers with the errno of a path nothing listens on. The binds of the grants come after, so a grant wins over a mount that names a path inside it (the exclusion list is the second line of that, and `the units` check it).
2. **Rejected: a view of the socket directories** (a tmpfs over `/run`, `/tmp`, the temp directory, with the allowed paths bound back). It leaves out a socket kept elsewhere (`~/.docker/desktop/docker.sock`, `~/.ssh` control sockets), which is the reason the plan names. It also breaks what the target reads: `/etc/resolv.conf` is a link into `/run/systemd/resolve` on systemd hosts, which an entry that declares `network: host` needs until Story 1.83, and a read of an existing file under the temp directory would become an unreported `ENOENT` (`traceDecision` leaves a read of a missing path out), which changes the audit's contract that reads elsewhere are allowed and listed. The cases that read an ungranted file under a temp directory would also need a new home.
3. **Rejected: a root of the target's own with only the allowed paths bound in.** It is the only mechanism that covers a socket bound after the call started, and it gives up the contract above for every target: a toolchain under `~/.nvm`, a global install under `/opt`, a cache the target reads would each need a declaration, and the list of system paths would turn from an audit exemption into an access control.
4. **Rejected: Landlock's rule on connecting to a socket path.** The CI runners' kernels may not have Landlock, this container's does not (`ENOSYS`), and the file rights of the ABI the header lists include none for connecting.
5. **Rejected: a seccomp filter.** A filter sees the registers of `connect()`, and the socket's path is behind a pointer it cannot read, so it cannot tell an abstract name from a path or a port (the reason Story 1.63 recorded for abstract sockets). Blocking `AF_UNIX` altogether would cut the bridge, the shim and the stdio of every `child_process`.
6. **The list: the kernel's table, then two more sources.** `/proc/net/unix` names every bound socket of the network namespace by the address it was bound with, the one place that names a socket whatever directory it sits in. The table is read twice and the paths of both reads used, since the kernel serves it in pieces. Two review findings widened it. A socket a process moved after it bound (OpenSSH's control master binds a temporary name and links it to the final one, so the table holds a path that is gone) hides the socket files beside that path, ranked by owner (Decision 17). A socket the table does not hold (the Docker socket a container job shares from the host, bound in another network namespace, and a socket bound by a relative path) is found by walking `/run`, `/var/run`, `/tmp` and `/var/tmp` one directory down, reading at most 2,000 directories of a root in name order. A path joins the list only after `lstat` on its exact path finds a socket file, names are read as bytes and one that does not round-trip through UTF-8 is skipped, and the list ends at 2,000 sockets (Decision 14).
7. **Excluded from the mounts:** the call's grants (workspace, private directories, the home), the evaluation folder, the project's git directory and its alternates, the private root and `/run/user`, each either the call's own or already covered by a later `--tmpfs`. A mount in a covered directory would make Bubblewrap create its mount point in a read-only file system.
8. **The mounts apply to every Bubblewrap target, whatever its entry's `network`.** A `host` entry keeps the host's abstract sockets until Story 1.83, but the socket files are a separate route Story 1.82 owns. Nothing offers an escape short of `"confinement": false`: a target that needs a host service through a socket file is outside what the sandbox can keep, as one that needs the host's network was in Story 1.63.
9. **A call is started again over its own list when Bubblewrap could not start over a socket that went away.** The window between the list and the mount is a few milliseconds, and a host with sockets that come and go (test servers, sessions) would turn it into flaky infrastructure errors. The retry fires only when the status file holds the runtime's own untouched line (`started === false`, so a target that damages its status file is not run again, and a tool server or command whose shim ran, signed started status included, is never run again), a hidden socket no longer is one, and the run was not aborted. The second start mounts the first list without the sockets that vanished, never a list read again: a fresh list admits whatever another process created meanwhile, and under churn (200 socket files another user creates and removes on a loop) 17 of 20 calls failed after three starts on a fresh list. Each retry has fewer sockets than the start before, so the starts are bounded by the list and no fixed count is needed; in the same container the churn run (the review's `inside3.sh`, 200 files) ended 20 of 20 calls with 125 starts in all. The tool-server path catches the adapter's `SessionEnded`, which the adapter throws when a server ends before it answers, reads the status and applies the same rule.
10. **A socket path goes into the vector as it is.** The profile-safe check exists for Seatbelt's profile strings; an argument carries any character but NUL, and `/proc/net/unix` lists the sockets of every user, so a refusal would let any local user stop every Bubblewrap call by binding `/tmp/a"b.sock`. The same holds for a line break in a file name under a scanned root: the list finds it and the file the launcher hands Bubblewrap (Decision 15) carries it, since its arguments end at a NUL. The refusal of Decision 14 keeps the rule: it fires on a count that only root, a system account or the runtime's own user can reach, so no other local user can stop a call with it.
11. **The evaluation layer's vector has no mounts.** Its `/` is a writable bind, so a mount over a socket that went away would create an empty file on the host. Story 1.88 files the layer.
12. **macOS is unchanged.** The Seatbelt profile names sockets by path, so a rule there can also cover a socket bound later; Story 1.87 files it, and the reference says a macOS target reaches a path-based socket outside the private root (a case connects).
13. **The reference's claims.** Each new sentence is a claim of `the network reference` that names the cases backing it, so a sentence no case backs fails. The old sentence is gone, and `the network reference` fails while it comes back. Review round 2 replaced the bounds sentence with five (the room, the ranking, the refusal, the record of what the room cut and the exact-path rule), each naming `the path socket units`, and the record sentence also names `the run and its scores` and `the audit's channel`, which hold the `hostSocketTruncation` list of a real run.
    Review round 3 changed the ranking sentence (the last rank is taken in turns by owner, so a local user who makes sockets in bulk cannot push out another user's socket while the room left after the first three ranks holds one socket for each owner), added the sentence of the `run.json` field list (`hostSocketTruncation`, backed by the units, `the run and its scores` and `the host socket record`) and named `the host socket record` in the record sentence.
    Review round 4 added four claims: the neighbors' order, the one bound that remains beside a moved path, the launcher's environment (every variable whose name is a valid shell identifier and that the shell does not initialize, and the seven the launcher restores) and its limit (a name no shell can hold, an exported shell function, the variables bash initializes itself, with Story 1.89 named as the close), each backed by `the path socket units`.
14. **The mounts go through `--args`, and the list is ranked by who can create a socket and sized to the call's own command.** Review round 1 found that another local user can stop every call with socket files: 30,000 of them in `/tmp` overflow the `exec` argument limit.
    The first fix, the mounts through `bwrap --args <fd>`, moves them out of `exec`'s arguments (a long path no longer risks the byte limit; 30,000 paths are about 2 MB of arguments), and Bubblewrap's own limit then shows: in the container (bubblewrap 0.8.0), 2,995 mounts start and 3,000 fail with `bwrap: Exceeded maximum number of arguments 9000`, a total that counts what `--args` reads.
    A refusal on a count any user can reach is a denial of service, so round 1 cut the list at 2,000 sockets in the order of its sources (the kernel's table, the neighbors of a moved path, then `/run`, `/var/run`, `/tmp` and `/var/tmp`, each sorted).
    Review round 2 found that cut fail-open and the bound wrong for a long command, both reproduced in the container:
    - **The cut let a local user push a service out.** Group 0 was every path of `/proc/net/unix` sorted by string, so 2,000 live sockets bound by another user at paths that sort before `/run` (`/dev/shm/...`, `/home/<them>/...`) left `/run/docker.sock` and `/run/dbus/system_bus_socket` past the cut and all three targets answered `connected` (with 0 padding sockets all three answered `ECONNREFUSED`; with 2,100, `hidden: 2000`, neither path listed).
      A second route needs no descriptor: one socket bound then renamed plus 2,000 stale socket files in its directory fills the neighbor group, which runs before the scanned roots.
      The claim of this decision, that a padder can push a service out of the scan's share but not out of the table's, was false.
    - **The room ignored the call's own command.** Bubblewrap's 9,000 arguments count the whole command line, the target's arguments included, with what `--args` reads.
      With 2,000 mounts, a target with 100 or 2,900 arguments started and one with 3,100 failed with `Exceeded maximum number of arguments 9000`, where before this story the call ran with up to about 8,980 arguments.
      The measured edge in the container: a command of 11 words (`bwrap`, `--unshare-user`, `--ro-bind / /`, `--dev /dev`, `--args 3`, `--`, the target) plus 3,000 target arguments starts with 1,996 mounts and refuses 1,997, and with no target arguments it starts with 2,996 and refuses 2,997, so the bound is 8,999 arguments in all.
      The fix: (a) `/dev` and `/proc` leave the list (the vector replaces both with `--dev /dev` and `--proc /proc`, so a socket there needs no mount and takes no room; the `/dev/shm` padding of the reproduction costs nothing now).
      (b) The list is ranked before the cut by who can create a socket, from the owner `lstat` already reads: the well-known service sockets by name first (`PINNED_SOCKETS`: Docker, containerd, Podman, the system bus, systemd's private socket), then root and the system accounts (user IDs up to 999), then the runtime's own user, then every other user, and inside a rank the order of the sources as before.
      Review round 3 found that claim false for a third user: every other user shared one rank, ordered by source group and name, so one user's padding pushed out another user's socket (reproduced: `carol` serves `/tmp/carol/agent.sock`, `nobody` binds 2,100 live sockets at `/home/pad/a*`; without padding her socket is listed and answers `ECONNREFUSED`, with padding it is not listed and the target connects, report `{"calls":2,"truncatedCalls":2,"socketsLeftReachable":102}`).
      The rank of every other user is now taken in turns by owner, the first socket of each owner (inside an owner, the order of the sources and then the name), then the second of each, so a local user who makes sockets in bulk cannot push out another user's socket while the room left after the first three ranks holds one socket for each owner (a room of two for three owners lists two owners' first sockets, which a unit holds as the stated bound).
      Chosen over rewording the claim to "only the sockets of ordinary users" since the interleave is small, deterministic and held by a unit that fails on revert.
      Review round 4 found the loop of Decision 17 outside that guarantee: it counted every neighbor against one global room before any ranking, so another user's bulk sockets pushed out the runtime user's own, root's and a third user's moved sockets; Decision 17 carries the fix.
      (c) A call is refused with exit 12 and a named reason (the count of sockets of the first three ranks, the room, and the arguments the call's own command takes of Bubblewrap's 9,000) when the sockets of those three ranks alone exceed the room; no other user can cause that, which is the rule of Decision 10.
      (d) The room is computed for each call from its own command: the command is built without mounts, `--args <descriptor>` is added, and `floor((9000 - arguments - 8) / 3)` (at most 2,000) goes to the list as `limit`; the 8 held back and the formula land every command between 8,990 and 8,992 arguments in all, inside the measured 8,999.
      A list longer than the room that anything hands the call is refused at the call, so the bound holds in one place.
      A retried call keeps its own list, a subset of the first, so it fits the same command (no second list is asked for).
      (e) What the room cut stays reachable and is recorded: the sandbox counts the calls that listed, those the room cut and the most sockets one call left (`socketReport`), the trial's port hands the report to the run, and `run.json` lists each trial with a cut call under `hostSocketTruncation` (`conditionArm`, `trialIndex`, `calls`, `truncatedCalls`, `socketsLeftReachable`; an empty list otherwise), as `observedMountsChannel` lists the audited trials and `hostNetwork` the entries that keep the host's network; the run's summary names those trials as it names the lossy ones.
      After the fix the reproduction in the container, with 2,100 sockets of `nobody` at `/home/pad` (sorting before `/run`) or at `/var/tmp/pad`, lists `/run/dbus/system_bus_socket` and `/run/docker.sock` among the 2,000 hidden (102 cut and recorded) and all three targets answer `ECONNREFUSED`; with the padding in `/dev/shm` the call hides 2 sockets and the targets answer `ECONNREFUSED`; with 2,100 sockets and a target of 3,100 arguments the call hides 1,952 (150 cut) and starts, and with 8,900 arguments it hides 19 and starts.
      A host that runs the list at the room (the container with 30,000 files: 3 calls in 5 seconds with 2,000 mounts each) still starts every call.
      The case with 30,000 sockets in `/tmp`, run as `tester` with files `nobody` made, failed with `could not start the target` before round 1 and passes with 3 of 3 calls after.
      The users of IDs up to 999 are the host's own on the Linux distributions the CI runs; a host that gives ordinary users IDs below 1,000 would rank them with root, which fails closed with a refusal.
15. **A launcher opens the arguments file.** `eval-quality` spawns the command, so the runtime cannot pass a descriptor to `bwrap` itself. A call that hides sockets starts `/bin/sh -c 'exec 3<"$1" || exit 126; shift; exec "$@"'` with the file as its first argument and the rest of the command after it, outermost and before `strace`, so the process that runs is `strace` or `bwrap` in the shell's place (`exec`), the audit traces Bubblewrap alone, and the vector carries `--args 3` where the mounts went. The file (`sockets-<n>-<token>.args`, mode 600) sits in the status directory, is removed when the call ends and with the run's scratch when a run is killed. A call that hides no socket has no file and no launcher. The mounts are the same bytes: the golden holds the vector with `--args 3` and the file's arguments as a new output.
    Review round 2 found that the shell changes the target's environment: dash hands the program it executes `PWD=/` (an inherited `PWD` is rewritten, an unset one is set) and bash as `sh` decrements `SHLVL` and sets `_` and `OLDPWD`, so the target's environment depended on the host's socket count.
    The launcher now ends in `/usr/bin/env`, which removes (`-u`) each of `SHELL_VARIABLES` the call's environment did not hold and sets each one it did hold to its value, with the options first since `env` reads an assignment as their end; the call's environment reaches `wrap` as an option (`environment`) from both mechanisms.
    Review round 3 found the list short: dash's init also resets `IFS`, `OPTIND` and `PPID` whenever the environment holds them (`{PATH, FOO=1, IFS=x, OPTIND=5, PPID=7}` reached the target as `IFS=x OPTIND=5 PPID=7` with no hidden socket and as `IFS=<space><tab><newline> OPTIND=1 PPID=19` with one), so `SHELL_VARIABLES` is `PWD`, `OLDPWD`, `SHLVL`, `_`, `IFS`, `OPTIND` and `PPID`.
    The shell with `env` stays. A tiny exec helper that opens the descriptor would need a native build, which this change excludes, and no interpreter on every host can replace the process it runs in without a shell (`node` has no `exec`).
    The choice is proved with a full `env` comparison in the container (dash as `sh`): a call with 42 variables set, among them every variable dash, bash and ksh initialize, prints the same environment through the launcher with the restoring `env` as without it, and the unrestored shell differs in `IFS`, `OPTIND`, `PPID` and `PWD` alone.
    A first word with `=` in it would be read by `env` as an assignment, so such an executable path is refused.
    Review round 4 found the claim wider than the code: the target's environment still depends on whether sockets are hidden for the names a shell treats specially.
    Under dash a variable whose name is not a valid shell name (`BASH_FUNC_f%%`, `my.setting`) is dropped when a socket is hidden; under bash as `/bin/sh` a held `PS1` is dropped, `PS2`, `PS4`, `LINENO`, `RANDOM`, `SHELLOPTS`, `BASHOPTS`, `BASH` and `BASH_VERSION` are rewritten and `BASH_FUNC_*` is re-serialized.
    The claim is narrowed in the CHANGELOG, the reference, the amendments, the code comment and the case text: the launcher leaves the environment as the call gave it for every variable whose name is a valid shell identifier and that the shell does not initialize, and restores `PWD`, `OLDPWD`, `SHLVL`, `_`, `IFS`, `OPTIND` and `PPID`.
    The limit is stated in the reference and held by a case that compares the control (no hidden socket holds each variable exactly) with the hidden call (at least one of the three differs on the host's `sh`).
    No list of names and no rewrite of the launcher goes into this pull request, since a list of the shell's special names does not end; Story 1.89 replaces the shell with an exec helper or hands the exact environment to `confinement-status.cjs`, and turns the limit case into a byte-identity case on dash and on bash as `sh`.

## Limits the reference states, and the stories that follow

- A socket bound after the call started stays reachable for that call; one unlinked and bound again too (a daemon restart); one bound in another network namespace outside the scanned directories; one whose path holds a line break in a directory outside the scanned roots (a line break in a file name under them is found and hidden); one whose file name is no UTF-8; one of another user's past the call's room (at most 2,000 sockets, fewer for a call whose own command is long), past the 2,000 directories of a root or, beside a moved path, past the room as one owner's socket files (Decision 17); a hard link or a second mount of the same socket file. Each limit has a case: the units hold a table row split by a line break, a file name with one under a scanned root, a name that is no UTF-8, a list past the room (with its rank, its refusal and its record), a scan bounded in directories and a hard link, and the route case plants a name that is no UTF-8. A connection to one is not audited yet: **Story 1.86** lists it as an observed mount (`connect` is no file syscall, so `strace` traces none today).
- A call that hides sockets can change or drop a variable of the target's environment whose name a shell cannot hold (`my.setting`, `BASH_FUNC_f%%` under dash), an exported shell function and a variable bash initializes itself (`PS1`, `PS2`, `PS4`, `LINENO`, `RANDOM`, `SHELLOPTS`, `BASHOPTS`, `BASH`, `BASH_VERSION`, with `sh` as bash), which `the path socket units` hold and **Story 1.89** closes by taking the shell out of the launcher.
- The evaluation layer's processes keep every host socket, so a sealed-brief agent run by a user in the `docker` group can start a container that writes the evaluation folder: **Story 1.88**.
- A macOS Seatbelt target reaches a path-based socket outside the private root: **Story 1.87**.
