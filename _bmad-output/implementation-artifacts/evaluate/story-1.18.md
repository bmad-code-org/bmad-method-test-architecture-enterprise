## Intent

**Problem:** Story 1.8's arm executor sends literal bindings only and stops a trial with exit 12 on a `captured` binding, so a workflow whose later step needs a value an earlier step produced (an identifier `create` mints, read back by `read-back`) cannot be evaluated over its own interface kind, as AD-4's workflow row states.

**Approach:** the arm executor resolves each `captured` binding from the named earlier observation of the same arm, through eval-quality's own pointer reading, orders the plan over its `after` and capture edges, and does not issue a step whose captured value or `after` step is missing, recording the skip, so eval-quality reads the missing observation as it reads any absent evidence.

## Boundaries & Constraints

**Always:** eval-quality decides what a captured pointer resolves to and what a missing observation means (AD-1); `engine.js` stays the one runtime file that loads eval-quality; `compile` owns every plan-shape refusal (a cycle, a dangling capture, a nested `after`); every run-directory write goes through `run-directory.js`; `matcher` and `principal` bindings keep stopping the arm with exit 12 (Story 1.30).

**Never:** a verdict computed in TeA from a skipped step; a copy of eval-quality's selection, tiering or capture typing; a `check` rule restating a compile code; an edit to eval-quality.

**Decisions (build agent, owner-delegated):**

- A captured value is read by eval-quality's exported `makeResolveOperand` over the record observations the arm has recorded so far, the same `walkTail(channelRoot(...))` reading `score` gives the pointer (`dist/core/score/bindings.js` `resolveCapturedValue`), so the value sent is the value `score` compares the observed call input with.
  The plan schema names the source as `{ "captured": "/interactions/<stepId>/<channel>/<key>" }` (`dist/core/schemas/plan.js`, `InteractionPointer`); compile holds the channel to the one the operation's response descriptor describes and the tail to one declared scalar key (`dist/core/compile/bindings.js`).
- "The earlier observation lacks the captured value" is `makeResolveOperand` answering `ABSENT`: the named step has no observation in this arm (it was not issued), or its described channel lacks the key (a missing field, a channel that is not JSON).
  A failed step (a non-zero exit) that still printed the value is an observation holding it, so its value is sent, as `score` would resolve it; a JSON `null` is a value (AD-26 counts it present).
- A step whose `after` step (one the plan declares) was not issued, whose captured value is absent, or whose captured value the request cannot carry as the target printed it (a value holding a `__proto__` key, a header or environment value that is no string, a command argument, option or environment value holding a NUL character) is not issued: no request, no observation, no `sequence` consumed.
  The skip is decided once the request is built, so a binding kind or an operation the run cannot send stops the arm (exit 12) whatever the target printed; a value the target printed skips the step, since the target's output is behavior for eval-quality to judge.
  The arm's `steps` evidence lists the step in its place as `{ stepId, operationId, skipped: { reason, ... } }` (`after-step-not-issued` with the `after` step, `captured-value-absent` with each binding and pointer, or `captured-value-unsendable` with each binding, pointer and reason, the value quoted to 200 characters), and the trial's tool calls and call count leave it out.
  eval-quality reads the missing observation itself: in the fixture its witness match finds the signature's home operation unexercised and records the seeded probe `not-applicable`.
- The run order is the plan order constrained by each step's `after` step and every step its captures read, among the steps the plan declares; a name the plan does not declare adds no edge, as eval-quality reads a dangling `after` (permissive) and a dangling capture (absent), and compile refuses the dangling capture before any arm runs.
  Any topological order satisfies `score`, which holds a capture and an `after` clause to the record's `sequence` alone.
- `check` gains no rule: a capture naming a step outside the plan is compile's `unreachable-check-evidence`, a capture from a step that cannot run before it is compile's `binding-cycle`, and `preflight` and `run` pass compile's exit 4 and message through before any arm runs.

## I/O & Edge-Case Matrix

| Scenario               | Input / State                                                                | Expected Output / Behavior                                                                                  | Error Handling                       |
| ---------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| Workflow pipeline      | `read-back` listed before `create`, `after: create`, capturing `create`'s id | `create` issued first, `read-back` sent that trial's id; `passed-clean-control` and `caught`                | N/A                                  |
| Missing captured value | `create` prints no id in the mutated trials                                  | `read-back` not issued, no observation, skip recorded; P-002 `not-applicable` in each trial, never `caught` | N/A                                  |
| Cycle                  | `create` captures from `read-back`, which runs after `create`                | `preflight` and `run` exit 4 with compile's `binding-cycle` stderr verbatim, no arm run                     | N/A                                  |
| Unsendable binding     | a `matcher` or `principal` binding, a skipped step before it or not          | the arm stops                                                                                               | exit 12, as before                   |
| Unsendable value       | `create` prints a number for a header, or a string holding a NUL             | the dependent step not issued, `captured-value-unsendable` recorded                                         | N/A                                  |
| Cycle past compile     | a self-capture handed to `runArm` directly                                   | `ArmError` naming the step                                                                                  | exit 12; unreachable through the CLI |

## Implementation Notes

- **Implemented directly**, as Stories 1.8 to 1.32 were: this build runs as a subagent of the coordinator with the planning context loaded first.
  No file under the Evaluate skill changed: its contract and adapter guides are placeholders Stories 1.12 and 1.13 fill, and no asset carries an interaction plan, so the skill gates do not apply.
- **Engine facts checked in the published package (eval-quality 4.3.0).**
  `dist/core/schemas/plan.js`: `BindingValue` is `{ literal } | { matcher } | { captured: InteractionPointer } | { principal }`, and a step's `after` is one level only (`nested-temporal-clause`).
  `dist/core/compile/bindings.js`: `binding-cycle` fires on a cycle over the union of capture and `after` edges that holds a capture edge; `captured-channel-undeclared` holds the pointer to the described channel; `unreachable-check-evidence` holds it to one declared scalar key whose type equals the bound parameter's.
  `dist/core/score/bindings.js`: a captured value resolves by `walkTail(channelRoot(source, target), target.tail)` over the named step's selected observation, a candidate must come after it by `sequence`, and an unresolved capture filters every candidate out.
  `dist/core/score/witness.js` and `outcome.js`: a probe whose signature's home operation has no `evaluator-chosen` observation is `unexercised`, which the outcome table maps to `not-applicable`, an unvoted state (`reduce-trials.js`).
  eval-quality 4.3.0 blocked no criterion.
- **The fixture.** `bin/records.js create` reads a title on standard input, mints `rec-<UUID>`, stores it under `store/` and prints `{ id, title, path }`; `read --id` prints `{ found, id, title }`.
  The contract lists `read-back` before `create`, with `after: "create"` and `{ "captured": "/interactions/create/stdout/id" }`, so array order would send the read first.
  M-001 makes `create` store the record under a second fresh identifier; the defect's manifestation witness reads a single `create` leg (its printed `path` no longer holds its printed `id`), since eval-quality's preflight issues one leg per witness, and the defect signature names the `read` invocation (`found` is `false`), so a trial that never issues the read-back never exercises the signature's operation.
- **A missing value in the trials alone.** A `create` that omits the identifier in every run fails the clean control's and the mutation's qualification (exit 11) before any trial, so no evidence artifact exists to read.
  The fixture omits it only in the workspaces `RECORDS_OMIT_ID` names, the pattern `VERDICT_WHEN` set in Story 1.8, and the case names the mutated arm's three trials; each records `create` alone and lists `read-back` as skipped, and eval-quality scores P-002 `not-applicable` three times, `caught: false`.
- **Gap found and fixed: a copy workspace reproduced a changed pristine copy.** `createWorkspace` copied `basis.top` for every workspace made from the pristine copy, after the preflight legs had run there; the record store's `create` legs wrote records into it, so the clean controls' qualification workspace was refused ("the qualify-clean workspace digests to ..., not the ... of the workspace it reproduces", exit 12) and no stateful target could complete `run` in a copy workspace.
  The pristine copy now keeps `snapshot`, a copy of what it held when it was made, beside it in its own temp directory, taken once its links are contained and without its provisioned directories, and every reproduction copies the snapshot and provisions only the directories the pristine copy provisioned, from its read-only copies; everything the snapshot holds is under the tree digest, so a snapshot changed after it was made fails the digest check (exit 12).
- **Gap found and fixed: a gameability plan step read a command's output as text.** `syntheticPort` built a command step's observation with `stdout` tagged `text` whatever it held, while eval-quality's adapter (a real run) and the sealed-brief agent's gameability calls (`degeneratePort`) read JSON-shaped output as JSON; on a gameability arm a captured binding into command output, or an oracle pointing into it, resolved nothing.
  `degeneratePort` moved to `gameability.js` over a new `degenerateAdapter`, and `syntheticPort` answers every kind through that adapter, so a plan step and an agent call on a gameability arm are read and authorized alike; a plan step's committed answer gets no host value injected or scrubbed, so it reads the same on every host, and a registry denial exits 10 as on a real arm.
- **Shard weight.** `test:evaluate-workflow` takes about 20 s under c8 locally; its weight is 25, about 1.25 times that, as Stories 1.11 and 1.32 set theirs.
