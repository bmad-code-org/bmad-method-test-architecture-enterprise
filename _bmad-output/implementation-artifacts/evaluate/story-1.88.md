## Intent

**Problem:** The processes that run adopter or agent code for the evaluation (a `command` evaluator, a sealed-brief agent and the bridge relay it starts, the rubric judge, the evaluation's HTTP port) run under the layer's vector, whose `/` is a writable bind of the host's with the evaluation folder read-only.
They keep every host socket, so a sealed-brief agent run by a user in the `docker` group can start a container that writes the evaluation folder (AD-7, AD-8).
Story 1.82's mounts cannot be copied as they are: over a writable `/`, a mount over a socket file that went away between the list and the mount makes Bubblewrap create an empty file on the host.

**Approach:** each start of a Bubblewrap layer process lists the host's sockets again (the list a target's call reads, without the sockets the runtime serves itself) and, for each socket, binds the socket's own path onto itself and then mounts the empty device file over it.
Bubblewrap runs `realpath` on every bind source before any mount, so a socket that went away before the start stops the start and makes no file.
A socket its owner removes while Bubblewrap mounts it can leave an empty file at its path for as long as the process runs, and the runtime removes what Bubblewrap made when the process has ended and, for a killed run, at the next run's preflight.
The macOS layer profile carries the denial of Story 1.87, allows back the bridge's socket shape beneath the private root and the two system services, and denies every write to the bridge's directory.
The reference's sentence that the layer keeps every socket is replaced by the sockets the layer's processes cannot connect to and the ones they reach.

## Boundaries & Constraints

**Always:** the layer's vector with no socket to hide is the vector of Story 1.112 byte for byte.
No option in the layer's vector makes a file on the host, and no bind has a destination that its own bind does not stand on.
Every start of a layer process asks for the list again (`refresh`), and a list that does not fit the room the layer's command leaves refuses the start.
The sockets the runtime serves stay out of the list, so the bridge a sealed-brief agent's relay connects to stays connectable: the bridge registers its socket's path, device and inode when it listens, and a socket moved into the user's private root, `/tmp/tea-evaluate-p<uid>`, is another inode that stays hidden.
Every spawn site settles the guard when its process has ended, however it ended.
A Linux case runs where `bwrap` and `strace` start a user namespace and skips with its reason named elsewhere; the vector's text, the stand-in and the Seatbelt profile's text are held on every host.
The engine check runs at start and end.
No eval-quality change.
No skill file changes: `references/ci.md`, `SKILL.md`, `assets/evaluation-ci-plan.template.json`, every `capture-record.json`, and the exit-table rows the dogfood mutations replace stay as they are.

**Never:** a mount over a path that can be gone with no bind of that path before it, a shell launcher in the layer's command (Story 1.89 removes the target's), a new dependency, a container, a live run, a change to `cli/lib/isolate.js` or `cli/lib/atdd-isolation.js`.

## Probes

This host is macOS 27.0.1 on Apple silicon: no `bwrap`, no Linux, no container.
What Bubblewrap does is established from its documented behavior and from the story's own statement, and the ubuntu job proves the real run.

- `man bwrap` documents `--bind-try` and `--ro-bind-try` as "equal to `--bind` but ignores non-existent SRC", which says a plain `--bind` stops on a source that does not exist.
  A bind needs its source's type before it can prepare the destination (a directory is made with `mkdir`, any other source gets a file), so the source is read first.
- A bind of a non-directory source prepares its destination as a file when the destination is gone, which the story's Problem states and which over `--bind / /` is a file on the host.
- Path-based Unix sockets are file-system objects: `connect()` resolves the path to an inode and finds the listener by inode with no check of the caller's network namespace, which is why Story 1.82 finds the Docker socket a container job shares from another namespace.
- A Seatbelt layer profile with the denial and the allowances was run on this host with `sandbox-exec -p`: a socket under the temp directory answered `EPERM`, a socket under `/tmp/tea-evaluate-p501` connected.
- The sealed-brief agent's bridge socket lies beneath the private root (`bridge.js` `socketPlace`), and the HTTP port talks to the runtime over file descriptor 3 and to a started service over the host's loopback, so the layer's own Unix sockets are the bridge's alone.
- Review round 1, macOS (`sandbox-exec`, scratch probes in the scratchpad directory): under the first profile, which allowed the whole private root, a layer process renamed a user-owned directory that holds a host socket to `<root>/run-<name>/s-evil` and connected there (`renamed connected`); direct connection answered `EPERM`.
  Under the profile of the final tree the rename to a path of the bridge's shape answers `EPERM`, a rename elsewhere in the root succeeds and the connection there answers `EPERM`, the bridge's socket connects, and a write elsewhere in the root and in the temp directory succeeds.
  The target profile of Story 1.87 allows a `connect()` beneath the workspace and the call's private directories only, and its `(deny file-write*)` refuses a rename of a host directory, a rename of the socket file and a hard link into either (`EPERM` each), so a target has no such route; the case `the Seatbelt path socket route` holds the rename.
- Review round 2, macOS (`sandbox-exec`, `final-tree` copies): at `f4bc6c93` a layer process renamed a prepared tree `<staging>/s-B/bridge.sock` to `<root>/run-<name>` and connected at `<root>/run-<name>/s-B/bridge.sock` (`renamed connected`), since Seatbelt checks the rename against the renamed entry's own path and the profile denied only the shape's directory.
  With the root and each entry directly in it denied, the same rename answers `EPERM`, a layer process writing a record file into the root answers `EPERM`, a write beneath an existing `run-<name>` succeeds and the bridge's socket connects.
  A forged record (`mask-<dead pid>-<hex>.json`, mode 0600, `launchedAt: 0`, `state: 'absent'`) written under the profile of round 1 made the next unconfined preflight `unlink` an empty no-write-bit file and `rmdir` empty directories in the evaluation folder and the git directory; both layers of the fix (the profile and the sweep's file checks) are held by cases that fail without them.
- Review round 1, Bubblewrap v0.9.0 (`bubblewrap.c`, read from its source): `resolve_symlinks_in_ops` runs `realpath` over every bind source before any mount (`Can't find source path <S>`).
  `setup_newroot` then handles each op in turn: `get_file_mode` on `/oldroot/<source>` (`Can't get type of source`), `mkdir_with_parents` on the destination's parent, `ensure_file(dest, 0444)` (a `creat` of an empty file when the destination does not stand), and the mount.
  The destination is a path under `/newroot`, which `--bind / /` makes the host's own file system, so the empty file and the directories land on the host.
  No bind option skips the destination's creation (`NO_CREATE_DEST` is reachable only through `--hostname` and `--chmod`, and the `-try` forms skip a missing source only).
  `--info-fd` and `--json-status-fd` report the child's pid in the parent right after the clone, before the child's `setup_newroot`; the `exit-code` they report at the end follows the process; `--sync-fd` only stays open for the sandbox's life; `--block-fd` makes the child wait after `setup_newroot` and after the privileges are dropped, and no descriptor tells the parent that the child has reached that point.
  No signal fires after `setup_newroot`, so the guard acts when the process has ended.

## Decisions

1. **Bind the socket's own path onto itself, then mount the empty device file over it, and remove what Bubblewrap made when the process has ended.**
   Bubblewrap runs `realpath` on every bind source before any mount, so a socket that went away before the start stops the start with `Can't find source path` and makes no file.
   `setup_newroot` then reads each bind's source, makes the destination's parent directories and the destination as an empty file when it is gone, and mounts.
   No Bubblewrap option skips the destination's creation.
   A socket its owner removes after the `realpath` pass and before the mask's mount can therefore leave an empty file and the directories above it at its path on the host, for as long as the process runs.
   The file is a regular file with no content and no route to anything.
   The bind of the socket's own path first keeps a destination that went away from being made for a path the vector's own bind does not stand on, and the vector holds no option that makes a file (`bindsThatCanCreate`).
   The guard (Decision 14) removes the file and the directories when the process has ended, and the recovery of a killed run removes them at the next run's preflight.
   The round 1 review read the race between Bubblewrap's read of a source and the mask's mount from Bubblewrap's source, and the options that would close it inside Bubblewrap (a `mount(2)` helper, which needs `CAP_SYS_ADMIN`, a compiled helper and a launcher) were rejected for the story's Never list.
   Rejected: the mask alone after a check with `lstat`, which leaves the whole time between the check and Bubblewrap's mount, minutes for a vector kept across a trial, and makes the file the story forbids when the socket goes in it.
2. **Rejected mechanisms, each against Bubblewrap's behavior.**
   - A tmpfs over the socket's parent with the layer's needs bound back: a socket under `/tmp` makes `/tmp` the parent, every file the layer's processes make there would go to the tmpfs and be lost to the runtime, and the entries to bind back would exceed Bubblewrap's 9,000 arguments for a busy `/tmp`.
   - A bind with `--bind-try` or `--ro-bind-try`: they skip a missing source, and the mask's source is `/dev/null`, which is never missing, so the destination is still made.
   - An unshared network namespace for the layer: path-based sockets are files, `connect()` finds the listener by inode, and a namespace does not hide one (Story 1.82 reaches the Docker socket across namespaces); the layer also keeps the host's network for the HTTP port.
   - `--chmod` on the socket: it changes the host's inode, which is the host service's own mode.
   - An overlay of the socket's parent: the writes of the layer would stay in the overlay's upper layer, away from the host, and an overlay whose upper and lower layers are one directory is refused by the kernel.
   - A mount made by `mount --bind` in a namespace made with `unshare` before Bubblewrap runs: `mount(2)` never makes a destination, but the namespace needs a user mapping that changes the user the layer's processes see, depends on util-linux options an older host lacks, and the case could not run here.
   - Landlock's rule on connecting to a socket path and a seccomp filter on the address are the options Story 1.82 rejected, for a kernel the CI runners may not have and for a filter that cannot read the address.
3. **The list is read at every start (`refresh`), and the layer's vector is the one the spawn site asks for.**
   `layerPrefix` returns an array that carries `refresh` and `guard` as properties that are no argument, and each spawn site calls `launchPrefix` just before it starts the process, which calls `freshPrefix` and then the guard, and calls the `settle` it returned in a `finally` once the process has ended.
   A vector kept across a trial would name sockets that went away since, and each one would stop a start.
   Rejected: one list per run, which stales within seconds on a host that serves short-lived sockets; a refresh inside `layerPrefix` alone, since the prefix is built once at several call sites and reused.
4. **The sockets the runtime serves are the ones left out of the list, besides `/dev`, `/proc` and `/run/user`.**
   The runtime serves the bridge a sealed-brief agent's relay connects to beneath `/tmp/tea-evaluate-p<uid>`, and the relay runs in the layer.
   The HTTP port talks over a pipe and to a started service over the host's loopback, so the bridge is the one socket the runtime serves a layer process.
   `bridge.js` registers each bridge socket's real path, device and inode when it listens (`registerServedSocket` in `host-sockets.js`), and `layerSockets` drops a listed path only when `isServedSocket` finds all three.
   The registry lives in `host-sockets.js`, which both files already depend on or may require, and the bridge requires it when it opens a bridge, since the relay is the same file run as a program and needs no runtime module.
   A host socket a layer process moves into the private root (the layer's `/` is writable, and the first build left the whole root out of the list) is another inode, so the next start masks it; a socket renamed over the served socket's path is another inode too.
   Rejected: leaving the private root out of the list, which the first build did and which let a layer process move `/tmp/tmux-<uid>/default` or `/tmp/ssh-*/agent.*` into the root so that every later start listed it unmasked; leaving out one run's parent alone, which needs the scratch list at every spawn site.
   The registry does not fit the Seatbelt layer: a profile is text that names paths, so the bridge's socket shape and the write denial (Decision 13) carry the same promise there.
5. **A list that does not fit refuses the start.**
   The target's call records what the room cut (`hostSocketTruncation`) and refuses only when the first three ranks overflow; the layer has no record to name a cut socket in, so it refuses on a refusal, on a cut socket and on a list longer than the room.
   The room is `floor((9000 - (vector + 1000 held back for the command) - 8) / 6)`, at most 2,000, six arguments for each socket.
   Rejected: reaching sockets silently past the room, which leaves a host service reachable with no trace.
6. **The masks come after the layer's read-only binds.**
   A socket inside the evaluation folder or the git directory is hidden too, since a read-only bind of a directory is made from the host's own file system and would show the socket again if it came after the mask.
7. **The macOS layer profile closes the sockets with the rule of Story 1.87.**
   The title and the Problem name the evaluation layer, whose profile Story 1.87 left alone, and a macOS adopter's agent reaches Docker Desktop's socket the same way.
   `seatbeltSocketRules` builds the rules for the target's profile and the layer's, so the two cannot drift; the layer's allowances are the bridge's socket shape beneath the private root (Decision 13) and the two system services.
   Rejected: a Linux-only change, which leaves the layer of the host this project is developed on open.
8. **A layer process that serves a Unix socket of its own anywhere but the bridge's socket shape cannot connect to it on macOS.**
   Seatbelt has no predicate for a socket the process made itself, so the rule names paths.
   The reference says so and names the loopback port as the route.
   Under Bubblewrap the list is read at the start, so a socket the layer's own process binds later is reachable.
9. **A socket bound after the start stays reachable under Bubblewrap.**
   A mount covers the file as listed, and the reference says so for the layer as it does for the target.
   The layer's processes are not audited, so no observed mount lists the connection.
10. **The stand-in for Bubblewrap.**
    `BWRAP_STAND_IN` follows Bubblewrap v0.9.0's order over the host's own file system: a `realpath` pass over every bind source (`Can't find source path`), then for each bind the source's type (`Can't get type of source`), the destination's parent directories, an empty 0444 file where the destination of a non-directory source is gone, and the mount (`Can't bind mount`).
    It reads `stand-in.json` beside it, so a spawn site that gives the process a minimal environment still reaches it, and the file can stage the race: remove a path, or a whole directory chain, just before or just after a bind's source is read, and bind a socket again.
    It models the rules on every host, so a case that vanishes a socket and reads the directory afterwards runs on macOS too.
    The real Bubblewrap runs the same vector in `the layer path socket route`, which only the ubuntu job runs; a race between Bubblewrap's check and its mount cannot be staged against it deterministically, so the stand-in cases carry the race and the route carries the start that a gone socket stops and the control whose empty file `settle` removes.
11. **A layer that cannot start reports it as a host condition.**
    A `ConfinementError` from the list or from the guard at a spawn site becomes an `EvaluatorError` in the command evaluator (the run's exit 12) and a `PortProcessError` with exit 12 in the HTTP port, and `runDriven` in `cli/evaluate.js` ends a driven command with exit 12 and the message alone, where it was a stack and exit 1 before.
    The first build put that mapping in `main`, where it was unreachable: `runDriven` catches every error of a driven command first and printed the stack with exit 12.
    The HTTP port reads Bubblewrap's `Can't find source path` and `Can't get type of source` on its standard error as exit 12 when the child ended before it answered: the first is what Bubblewrap says for a socket that went away before the start (`resolve_symlinks_in_ops`), the second for one that went away between that pass and `setup_newroot`, and exit 10 says the port does not serve.
    Round 2 narrowed the match: the port itself can print `bwrap: Can't ...` and exit before it answers, which is the port's own failure.
    The diagnostic counts only when it opens the process's standard error (Bubblewrap prints it before it runs the port, so nothing the port prints can precede it), the status is 1 (Bubblewrap's own failure status) and the port had not answered; the same text after another line, with another status or after an answer keeps exit 10.
    The first build matched the second message alone, so the usual case exited 10, and its stand-in printed that message for it.
    Rejected: a retry at each spawn site, which would start a process again over a list read again and needs a way to tell Bubblewrap's own failure from the process's at five sites that read their children differently; the list is read just before the spawn, so a socket can go away only between that read and Bubblewrap's check of the sources.
12. **Guides.**
    `references/run.md`, `references/gaps.md` and `references/harness.md` name what a confined target reaches and stay true.
    `references/evaluator.md` is a skill guide that the workflow builder owns (AD-16 to AD-18), so the sentence on the evaluator's reach is in the reference alone.
13. **The macOS layer profile allows one shape of path and denies writes to the root, to each entry directly in it and to that shape.**
    The first build allowed `(subpath <private root>)`, and a layer process, which runs under `(allow default)`, renamed a user-owned directory that holds a host socket into the root and connected there.
    Round 1 allowed `(regex #"^<root>/run-[^/]+/s-[^/]+/bridge\.sock$")` for each spelling of the root (`/tmp` and `/private/tmp`), which is the shape `makePrivateParent` and `socketPlace` give the bridge's socket, and denied writes to `^<root>/run-[^/]+/s-[^/]+(/|$)`.
    Seatbelt checks a rename against the path of the entry that is renamed, so that denial missed the directory one level up: a layer process built `<staging>/s-B/bridge.sock` (a user-owned host socket file renamed there) and renamed the staging directory to `<root>/run-<name>`, and the connect at `<root>/run-<name>/s-B/bridge.sock` then matched the allowance and reached the host service.
    The profile now also denies `(regex #"^<root>(/[^/]+)?$")` for each spelling of the root, in the same `(deny file-write* ...)` rule: the root itself and every direct entry of it.
    The layer then cannot create or rename a `run-*` directory, rename the root or write a file in the root, while a write beneath an existing `<root>/run-<name>` (the layer's scratch directories) stays allowed and the bridge's `connect()` needs no write.
    Rejected: the subpath allowance of the first build; the shape's denial alone of round 1; a denial of every write under the whole root, which the layer needs for its scratch directories beneath the run's parent.
    The target profile has no such route (Probes): its allowances are the workspace and the call's private directories, and a rename of a host directory into them is a write outside the grants.
14. **The guard records before the start and removes after the process.**
    `startMaskGuard` notes, right before the start, each hidden path and each directory above one by `lstat` (absent, or its type with device and inode), writes that in a record, and returns `settle`.
    `removePlaceholders` is the one rule teardown and recovery share: a hidden path is removed only when it was a socket or absent and is now a zero-length regular file the runtime's user owns with no write bit, stamped by a change at or after the start (two seconds of slack for coarse clocks) and born at or after the start; a recreated directory goes deepest first only when it was absent or another device or inode than before and is now empty, owned by the runtime's user, stamped at or after the start and born at or after the start.
    A path whose birth time reads 0 or is unavailable stays, since the rule cannot tell when it was made.
    The inode of a hidden path decides nothing: ext4 hands a freed inode number to the next new file, so the placeholder Bubblewrap makes can have the number the socket had, and round 2 took the clause that kept such a file out of the rule.
    The state before the start and the type of the file after it decide: the change of type from socket or absent to an empty regular file with the other fields is the discriminator, and a pre-start regular file is never removed.
    A directory that stood keeps its device and inode as one more reason to stay, which only leaves a directory in place.
