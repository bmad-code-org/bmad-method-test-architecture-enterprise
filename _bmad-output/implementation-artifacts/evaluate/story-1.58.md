## Intent

**Problem:** A sealed-brief agent evaluator's bridge configuration (`mcp-config.json`, which carries the one admission token), its socket, and the evaluator, judge and command-evaluator working directories are `mkdtemp` directories under the temp directory, outside the evaluation folder. A confined target runs as the adopter's user, so it can read the token before the agent connects, take the bridge's one admission, and read an evaluator's or judge's working files (AD-21).

**Approach:** The run makes one private parent directory when it starts, beneath one per-user root, registered in its `scratch` list, and every evaluation-layer private directory is created beneath it. The confinement withholds that one root from a target under both mechanisms. The root exists before any sandbox is built, so a leftover process keeps a profile that still covers directories made later, by this run or by another.

## Boundaries & Constraints

**Always:** Move into the private parent the directories `sealed-brief-agent.js`, `bridge.js` (config dir and socket dir), `judge.js`, `command-evaluator.js`, and the engine, qualification, score and aggregate directories make through `makeScratchDirectory`; a directory the target is deliberately granted (target tmp, audit report, status, port, the workspace) stays where it is. The parent is removed with `removeScratch` like any scratch directory, and the existing `finally` releases still run. Carry the root to `targetSandbox` the way Story 1.57 carried the git access: through every `registry.createProbePort` call (`run.js`, `historical.js`, `preflight.js`), with the source scan over those calls extended to the new option. Withhold the root under Seatbelt (`deny file-read* file-write*` over the subpath, plus a rule that refuses `connect()` to a unix socket under it, proved by the case) and Bubblewrap (`--tmpfs` over the root), and add it to the audit's `withheld` list. Every run's parent is made beneath one fixed per-user root (`/tmp/tea-evaluate-p<uid>` on POSIX whatever the run's `TMPDIR` is, mode 0700, made when absent, held by `lstat` to be a real directory the user owns), which no run removes; a run removes its own parent. The bridge's token exists only in a mode 0600 file beneath the parent, and the relay's environment carries that file's path. The agent's own connection and every layer process stay admitted: layer processes are not target-confined. Every profile path goes through `assertProfileSafePath`. The socket path keeps its length fallback (`socketPlace`: temp directory, then `/tmp`), so the root is made where a socket path still fits. Evidence, records and digests are unchanged. A profile change updates `test/fixtures/isolation-primitives/golden.json` with `TEA_UPDATE_ISOLATION_GOLDEN=1 npm run test:isolation-primitives`; read the diff and keep only the added rules. The engine check runs at start and end. No eval-quality change. `docs/reference/tea-evaluate-cli.md` gets a sub-heading of its own for the bridge passage (`#### The bridge's admission token` under `### The evaluation layer`) and the passage states that the confinement withholds the run's private directories, so the token is unreadable to a confined target; a case reads the passage under that exact heading. Amend AD-21 (or AD-8) by one sentence. Finish Story 1.57's housekeeping in this PR: its `sprint-status.yaml` row to `done` and `story-1.57.md` status to `done`. Update `CHANGELOG.md` under `[Unreleased]`.

**Never:** a token or private path written into evidence, records or logs, a change to what the profiles grant for the workspace, target tmp, report, status or port, withholding by name prefix across the shared temp directory (it would catch another run's directories and the granted ones), a new dependency, an opt-out run changed (`"confinement": false` keeps today's layout reachable), a Windows named-pipe change (Windows has no confinement).

## Implementation Notes

- The private parent is `workspace.js` `makePrivateParent(scratch)`: `mkdtemp` of `run-<6>` beneath the user's private root `/tmp/tea-evaluate-p<uid>` on POSIX, whatever the run's `TMPDIR` is (Windows has no confinement and keeps the temp directory). The root is made (mode 0700) when absent and held by `lstat` to be a real directory the user owns, with an open mode closed to 0700; a link, another owner or a failing `mkdir` refuses the run with exit 12 (`score` with its infrastructure exit); no run removes it, since another may be using it. The parent's name carries the run's process id (`run-<pid>-<6>`), so the test suites reap the parents SIGKILLed runtimes leave (`removeDeadPrivateParents` in `test/lib/scratch-directories.js`, at suite start and end, by dead pid); Story 1.54 owns the runtime's own reclaim. The socket path under it (`/tmp/tea-evaluate-p<uid>/run-<pid>-<6>/s-<6>/bridge.sock`) is far inside `MAX_SOCKET_PATH` (100 bytes), so the earlier temp-directory-then-`/tmp` fallback is gone. The parent is unshifted to the front of `scratch` (so the run's end removes it with everything beneath it) and recorded as non-enumerable `scratch.privateParent`, its root as `scratch.privateRoot`. `makeScratchDirectory` makes its directory beneath `scratch.privateParent` when set and in the temp directory otherwise, so the callers (`sealed-brief-agent.js`, `judge.js`, `command-evaluator.js`, `run.js`, `score.js`, `preflight.js`) needed no change, and a unit that passes `[]` keeps today's layout. `preflight.js` `pipeline` and `score.js` make the parent first thing in their `try`, before any sandbox exists. `bridge.js` `socketPlace(scratch)` makes the bridge's directory beneath it (`SOCKET_DIRECTORY_PREFIX` `s-`, `MAX_SOCKET_PATH` exported by `bridge.js`, which `workspace.js` imports, since the relay process runs `bridge.js` and must not load the workspace module); with no parent it keeps the old temp directory then `/tmp` fallback.
- Review round 1 (A): a Seatbelt profile that names one run's parent leaves a leftover process of an earlier run, or a target of a concurrent run, able to reach the next run's parent. The sandbox now takes the root (`privateRoot`), so every parent beneath it, made before or after the sandbox, is withheld. Review round 2: the first version placed the root by each run's own `TMPDIR` (the temp directory, or `/tmp` on the socket budget fallback), so two runs of one user with different `TMPDIR`s had different roots and a sandbox withheld only its own (reproduced: a long-`TMPDIR` run's token file read under another run's Seatbelt sandbox). The root is now always `/tmp/tea-evaluate-p<uid>`. Seatbelt names both spellings (`/tmp` and `/private/tmp`, from `spellings`), and Bubblewrap's `--tmpfs`/`--remount-ro` names the real path of a root that exists before any sandbox is built. `checkPrivateRootAcrossRuns` builds a sandbox for one run and makes a second run's parent afterwards with a token file and a socket, for four pairs of temp directories (both the suite's, a long second one, another short second one, a long first and a short second), and asks the sandbox for both (refused); its control, a sandbox over the first run's parent alone, reads the token and connects.
- Review round 1 (B): the relay's environment was `TEA_EVALUATE_BRIDGE_TOKEN`, readable by another process of the user (macOS `KERN_PROCARGS2`). The token is now written to `<bridge directory>/token` (mode 0600) and the relay's environment carries `TEA_EVALUATE_BRIDGE_TOKEN_FILE`; the unconfined relay reads the file at start. The unit asserts mode 600, 48 hex characters, and that neither the relay's environment nor its argument list holds the token; the confined case asserts the same over the configuration every agent run received, and that a confined target reads the file refused (and reads it in the opt-out control).
- The root reaches `targetSandbox` as `privateRoot`. Deviation from "through every `createProbePort` call": each call passes `privateRoot: registry.privateRoot`, a getter on the registry that reads the `scratch` list it was built with, because the nine call sites (`run.js`, `historical.js`, `preflight.js`) have the registry and not the scratch list, and threading the list through their callers would add parameters to a dozen functions for the same value. The source scan in `checkProbePortGitAccess` requires the option beside `git` in every call. A confined run whose registry has no root (a unit that builds one by hand) withholds nothing, as a port with no `git` option does.
- Seatbelt: after the git rules and before the evaluation folder's denial, `(deny file-read* file-write* (subpath <root>))` and `(deny network-outbound (remote unix-socket (subpath <root>)))`. The second is needed: a probe on this host (macOS) showed the file denial alone leaves `connect()` to a socket under the root open, and with the rule it answers `EPERM`; the case's Seatbelt revert check (rule removed) fails on exactly the socket attempts. Bubblewrap: `--tmpfs <root> --remount-ro <root>` after the git rules (the story names `--tmpfs`; the read-only remount matches the evaluation folder's and the git directory's). Every path goes through `assertProfileSafePath`; the audit's `withheld` list gains the root; `targetSandbox` refuses a workspace inside it. The forbidden-input note of the isolation manifests is unchanged text, since it is part of the records.

## Design Notes

A static list of private directories at `createProbePort` time would miss directories made later in the run, and a Seatbelt profile is fixed when a process starts, so a leftover process would reach any directory its profile does not name. One parent made at run start fixes both: the sandbox is built over a path that already exists, and its `subpath` rule covers children made afterwards. Withholding by prefix would hit other runs' directories and the directories a target must keep. The same parent gives Story 1.54 one path to mark and reclaim after a kill.
