## Intent

**Problem:** The trial's audit is a preload that only Node processes load (`confinement-guard.cjs`, through `NODE_OPTIONS`). A shell script, a Python program, a child started with a cleared environment or a native binary reads outside its grants unreported, and the report file the preload appends to is writable by the target.

**Approach:** Replace the preload with an audit the mechanism itself supplies, kept where no target can write it. macOS: the Seatbelt profile reports every `file-read-data` it allows outside the grants (`(with report)`) and tags every refusal with a per-sandbox token (`(with message)`), and a `/usr/bin/log stream` child the runtime owns writes the kernel's reports for that token to a file beneath the run's private parent. Linux: the runtime starts the Bubblewrap command under `strace -f --seccomp-bpf --decode-pids=pidns`, outside the namespace, and reads its trace file. Both feed one decision, which lists the paths the target's processes opened outside what they were granted as `observedMounts`.

## Boundaries & Constraints

**Always:** The audit sees every process of the confined command, whatever its language or environment, and lists a path once, by its real path, when a process (a) opens, lists, executes or reads a link at a path outside the sandbox's read grants, or (b) is refused a read or write of a withheld path (the evaluation folder, the project's git directory apart from the worktree's own entry, the private root apart from the sandbox's home) or a write outside what the sandbox may write. Read grants: the workspace, the call's temp directory and port directory, the private home, the worktree's own git entry and the private repository, the call's declared `systemPaths`, the operating system's directories (the guard's list; on macOS also the root directory literal, `/private/var/db/timezone`, `/Library/Preferences/Logging`, `/Library/Perl`, `/Library/Python`, `/Library/Ruby` and the account's `.CFUserTextEncoding`, which CoreFoundation reads from the account's home whatever `HOME` says; on Linux the root directory literal), the Node installation the runtime runs from (only its `bin` directory when its parent holds the user's home) and, under Bubblewrap, the status shim. A path that does not exist and a metadata probe (`stat`, `access`) are no read and are not listed, as before; the execution of a binary reads it, so an ungranted binary is listed like any file (on Linux by the path it was started by). A write is listed only when the mechanism refused it; a refused write of the worktree's own git entry or the private repository (git's index lock) is git's own and is not listed. On Linux a read under the operating system's read-only directories (`/usr`, `/etc`, `/lib*`, `/bin`, `/sbin`; not `/proc`, `/sys` or `/dev`, whose paths lead anywhere) is judged by the path the process asked for, since the system links its own files elsewhere (`/etc/resolv.conf` into `/run/systemd/resolve` on the CI runner, which the first CI run listed). On Linux a `package.json` that Node's loader looks for above the sandbox's home, in a directory the sandbox hides, is not listed.

macOS: the profile's report rule is `(allow file-read-data (require-all (require-not <each grant>)...) (with report) (with message "<token>"))`, placed after the base write rules and before every later rule. Seatbelt decides an operation by the rules that name it before the rules that name its wildcard, so a rule naming `file-read-data` overrides every later `file-read*` rule whatever their order (the first audited profile let the target read the contract); an audited profile therefore names `file-read-data` in each denial and re-grant that governs reads, which keeps the last matching rule winning. Every denial carries the sandbox's token (`tea-evaluate-audit-<16 hex>`); a refused write of the worktree's own git entry and the private repository is denied without it. The runtime starts one `/usr/bin/log stream --style ndjson --timeout 4h --predicate 'process == "kernel" AND eventMessage CONTAINS "<token>"'` per audited sandbox, its standard output a file in a directory beneath the run's private parent (`makeAuditDirectory`, the home's place; it refuses to make one without the parent), never a pipe (a stalled event loop dropped events from a pipe in the spike). A read is a `file-read-data` event, a refusal a `deny` event of `file-read-data`, `file-write-*` or a refused hard link (its source is listed); the `duplicate report` lines the kernel adds parse as the event they repeat; only the kernel's own messages count. Attribution is by token alone, so concurrent sandboxes and runs never see each other's events. `observedMounts()` first runs a barrier: a sandbox-exec of `/bin/cat` over a fresh sentinel file (killed after 3 s) under a profile that reports it with the token, repeated every 200 ms until the sentinel's report is in the file or 10 s pass. A barrier that times out with no events, a `log` child that ended while the sandbox lived, a stream that reported lost events and no read, and a `log` that never reported the start-up sentinel each make the run exit 12 naming the cause. The reports of a process still running after the barrier are not part of that trial. The channel is lossy: the log lost none of 3,000 reports at a quiet host's 440 a second, one to five of 1,600 on a host saturated by other work (the three readers of one token lost the same reports, so the loss is upstream of the reader), and 7 to 20 percent of a burst of 40,000 a second, each without a trace. An empty list from macOS therefore means that no report arrived; the reference says so, and Story 1.81 records the loss per trial.

Linux: `wrap` returns `strace` as the target and `strace -f --seccomp-bpf --decode-pids=pidns -y -qq -s 4096 -e trace=<the open, creat, write-path, readlink and exec syscalls, each with the optional ? prefix> -o <audit directory>/trace-<n>-<random>.txt -- <bwrap vector> <status shim> ...`. strace runs outside the namespace, so no target process can write the trace or signal the tracer, and the trace file sits beneath the withheld private root. Lines before the `execve` of the status shim (the node program whose arguments carry the call's status file name; Bubblewrap's own `execve` names the whole command, so the program tells them apart) belong to Bubblewrap's setup and are dropped. The parser joins `<unfinished ...>` and `<... resumed>` lines per pid, decodes strace's escapes in a path and in a descriptor's `<path>` annotation, uses an absolute path as it is, takes the directory of a relative path from the `AT_FDCWD<dir>` annotation `-y` prints, resolves a relative path of a syscall without a directory argument (or a bare `AT_FDCWD`) against its process's working directory, which the parser replays at the end of the trace in the order the target made the `chdir` and `clone` calls (a forked child copies its parent's directory at the call, a thread that shares it with `CLONE_FS` follows it, a vforked child's lines can precede its parent's `clone` return, and a namespace's `clone` returns the namespace's number, which `--decode-pids=pidns` names as strace sees it), and takes the real path of an opened file from the `= 3<path>` annotation. `--seccomp-bpf` is required: without it a syscall-heavy process ran 100 times slower in the spike (12 s against 0.12 s). The trace is read once the call ends (a process Bubblewrap leaves running ends with the call's process-id namespace), parsed in a stream, removed, and its paths are added to the sandbox's set. A call whose shim started and whose trace holds no start of it fails the audit for the rest of the sandbox's life: `observedMounts()` then throws the same error, so a swallowed error (a server call's) is not an empty list.

`selectConfinement` probes the observer before the run starts and refuses (exit 12, naming the cause and the `"confinement": false` opt-out) when it cannot observe, after the path checks that need no observer: on macOS a shell starts the stream and a sandboxed read of a fresh sentinel must come back through it within 5 s (an unreadable log, no privilege, a sandboxed shell); on Linux `strace` must be on `PATH` and a traced Bubblewrap run of a trivial reader must report the probe file (ptrace refused, Yama, a container seccomp profile, a strace that lacks `--seccomp-bpf` or `--decode-pids=pidns`). `confinement.observer` carries the executable.

The sandbox's API changes with it: `targetSandbox` takes `audit: { directory }` in place of `report`; `wrap(target, args, writable, readable)` takes the call's declared system paths; `environment()` and `settle()` and the `NODE_OPTIONS` preload are gone; `start()` (macOS: spawn the stream and wait for its first sentinel), `collect(wrapped, { started })`, `observedMounts()` (async) and `release()` (kill the stream) replace them; `createProbePort` returns an async `observedMounts` and its release stops the audit; `run.js` maps an observer that cannot start or confirm to exit 12 for the trial. `confinement-guard.cjs` is deleted. Profile and vector output without `audit` changes only by the report file's grant, which is gone, and the golden gains the audited outputs (`TEA_UPDATE_ISOLATION_GOLDEN=1 npm run test:isolation-primitives`, diff read). The reference's `### File-system confinement` is updated, with what the audit does not see: metadata probes, file access through `io_uring` (Linux), a binary reached through a workspace link (Linux), the reads of a process still running after the trial's barrier, and the lost reports of the macOS channel. No skill reference repeats the old sentence (grep). Story 1.63's first criterion loses its premise: no report file exists for a target to rewrite, and the coordinator amends it after the merge. A new `mkdtemp` in `cli/` is listed in `checkPrivateDirectorySources`. `CHANGELOG.md` under `[Unreleased]`. No eval-quality change, no new npm dependency, no native build; the Linux workflows install `strace` beside `bubblewrap`. Tests that expect the lossy channel to deliver a report repeat on macOS, only when every failure is a missing report.

**Never:** a Node preload or any code in the target's address space, a report file a target can write, an observer that reports nothing when it failed, a registry field (nobody needs one), a grant widened to make a clean target pass, an attribution by process id or process name, a Windows change.

## Implementation Notes

**Spike (macOS 27, this host), recorded before the Always clause.** `(trace "file")` writes nothing; `(allow file-read-data <filter> (with report))` and `(with message "<text>")` are accepted, `(deny ... (with report))` is rejected, `(deny ... (with message ...))` is accepted; a report and a denial both show in `log stream` as `Sandbox: <name>(<pid>) allow|deny(1) <operation> <real path>` with the message text on the next line, which makes attribution per sandbox exact. Several filters in one rule are any-of, so the report rule needs `require-all` over `require-not`. A read of a missing path, a `stat` and the exec of a granted binary raise no ungranted report; every process reads the root directory `/`, and `dyld` reads `/System/Volumes/Preboot/Cryptexes`. `log stream` is live about 60 ms after it starts. Through a pipe a blocked event loop lost events (850 of 3,000); written to a file, 3,000 of 3,000 and 4,000 of 4,000 (four parallel readers) arrived. The channel is lossy upstream of any reader: three readers of one token lost the same reports (1 in 400 to 1,600 under CPU saturation, none in 120 at a quiet host, 7 to 20 percent at 40,000 per second), silently, and a lost report is never late (4 s of waiting recovered none). Seatbelt applies the rules that name an operation (`file-read-data`) before the rules that name its wildcard (`file-read*`) whatever their order: the first audited profile let the target read the contract, which the existing suite caught. Linux, observed in Docker (Debian bookworm, aarch64, strace 6.1, bubblewrap 0.8.0, run with `--init` and `--security-opt seccomp=unconfined apparmor=unconfined systempaths=unconfined` so the nested namespace can mount `/proc`): strace outside Bubblewrap traces the whole namespace tree, prints `AT_FDCWD<cwd>` and `= 3<real path>` with `-y`, a namespace's `clone` returns the namespace's own pid (`--decode-pids=pidns` adds strace's number), `?name` makes an unknown syscall name harmless (`fchmodat2` is unknown to 6.1), and `--seccomp-bpf` cut a 200,000-call loop from 12.1 s to 0.13 s. This host has no `strace` and no `bwrap`; Docker stood in.

**Decisions.** (1) The preload and `confinement-guard.cjs` are deleted rather than kept beside the mechanism: the mechanism sees what the preload saw and more, and the preload's report file is what a target can rewrite. (2) Story 1.80 already exists in lane 2, so the appended story is 1.81 (the macOS channel's loss, recorded per trial); `epics.md` gets its section, the dependency row (rows after it renumbered), the lane list, `test-design-epic-1.md` its section and `sprint-status.yaml` its `backlog` row and `parallel_lanes` entry.
