## Intent

**Problem:** Evaluate has no CI stage. No file says what runs on a pull request, a merge, a schedule or a release, nothing replays a committed baseline to prove the evidence still reproduces, contract-source freshness, the gameability arm and oracle-versus-scorer agreement run in no tier, and exit 13 (AD-10's evidence drift row) is emitted by nothing.

**Approach:** `cli/lib/evaluate/ci.js` and `tea-evaluate ci --evaluation <folder> --tier <pr|merge|scheduled|release>` ship. The runtime owns the schema of `ci/evaluation-ci-plan.json`, validates the placement rules, and runs exactly the plan's checks for the tier. The `pr` tier replays a committed baseline through eval-quality's `preflight` and `score` in a scratch copy of the evaluation folder and exits 13 when the produced evidence differs. `check` gains contract-source freshness. Every stage exit passes through verbatim; CI computes no verdict of its own.

## Boundaries & Constraints

**Always:**

- The plan: `ci/evaluation-ci-plan.json` in the evaluation folder, schema `cli/lib/evaluate/schemas/evaluation-ci-plan.schema.json` (a JSON schema with `schemaVersion` const, read as `baseline.schema.json` is; `test:schema-versions` refuses a literal). Per check: `id`, `tier`, `trigger`, `kind` (`evaluate`: a `tea-evaluate` command, or `gate`: an `eval-quality-gates` command), `command` (argv array, no shell), `enforcement` (the AD-10 class), `evidence` (paths) and `placement` (`tier`, `defaultTier` from AD-10's table, `reason`). `ci` accepts a closed set of `evaluate` check ids, one per AD-10 default-tier member: `check` (freshness included), `compile`, `seal`, `api-conformance`, `gameability`, `oracle-agreement`, `replay`, `preflight-live`, `twin-run`, `held-out`, `judge-calibration`, `strength-comparison`; an unknown id fails validation. `ci --tier <tier>` runs exactly the plan's checks whose `placement.tier` is that tier, in plan order, and runs every one (a failed check does not stop the rest, so the evidence bundle is complete).
- Plan validation (exit 10, each a case): a check whose `tier` differs from `defaultTier` and has no `reason`; a deterministic check that needs no secret placed off `pr` (CAP-11); an `evaluate` command not led by `tea-evaluate`, a `gate` command not led by `eval-quality-gates`; a schema violation; a tier with no checks is not an error. A missing plan exits 64 (wiring), naming the path.
- Exits pass through verbatim. The final exit is the most severe blocking result, in this order (a coordinator decision, recorded in AD-10): 64, 12, 5, 4, 3, 13, 11, 10, 2, 1, then 0. CONCERNS read from the evidence artifact is a warn: exit 0 plus a warning line and a `warn` row in the summary. `--strict` is never passed. No check claims `evidence-over-truncated`, `evidence-unavailable` or `evidence-internally-inconsistent`.
- Persistence: `runs/<invocationId>/` (created through `RunDirectory`, so the write rules of Story 1.8 hold) holds, per check, `checks/<id>/exit-code`, `stdout` and `stderr` byte for byte, plus `ci.json` (tier, per-check id, exit, class, action `pass|warn|block`, evidence paths, the final exit). A `gate` check runs as a child process with no shell and the argv from the plan; its three outputs are persisted whatever its exit.
- Replay (`pr`): reads baseline bytes only from `baseline/`. It builds a scratch copy of the evaluation folder (a runtime scratch directory on the pipeline's scratch list, removed on every exit path), places the baseline's bytes at `runs/<acceptedRun>/` in it (minus `baseline.json`), runs eval-quality's `preflight` over the baseline's `contract.json`, `probes.json` and `observations.json` and compares the verdict with `preflight-verdict.json`, runs `score` over it through `runScoreCommand`, and compares the produced per-probe evidence artifacts and the strength aggregate with the baseline's latest `scores/<id>/` subtree. Produced evidence is written to the real folder's fresh `runs/<invocationId>/replay/`. A difference, a missing file or an extra file exits 13 (class evaluation evidence drift, action block). The stage exits themselves pass through; 13 applies when they are 0 or 2 and the bytes differ. Determine empirically which produced files are deterministic (record the list in Implementation Notes); never exclude a file to make a case pass.
- Stale baseline: the replay runs against the baseline's own snapshot. When the current contract, corpus or `policy/` digest differs from `baseline.json`'s, `pr` warns and `release` blocks (exit 11).
- Freshness lives in `check`: `sourceSpecDigest` in the contract against `digestBytes` over the committed `requirements.md` that `evaluation.json` `requirements` names; a mismatch or a missing statement exits 10 for every evaluation. This story back-fills `requirements.md`, the `requirements` entry and the matching `sourceSpecDigest` for the eight fixtures that predate Story 1.12 (`test/fixtures/evaluate/valid`, `preflight`, `mutation/evals/verdict`, `evaluate-mcp`, `-api`, `-workflow`, `-tool-use-agent`, `-promptfoo`), regenerating whatever digests that moves (contract, seal, corpus, committed probes) with the repository's own generators, and the Epic 1 `test:evaluate-*` suites stay green.
- Agreement: read `corroboration` on each oracle outcome in the baseline evidence; TeA holds no comparison table. Any `disagrees`, or a required oracle that is `not-evaluable` or `unreached`, exits 11.
- Gameability: the `pr` tier scores the gameability arm of every gameability probe through `score` over the baseline records (Story 1.9: no target launches); a launch marker the stub target would write stays absent.
- `scheduled` and `release`: live preflight, a twin run at `minimumTrialCount`, the held-out partition (Story 1.21) with the strength floor applied to it separately, judge calibration when the contract declares a rubric (exit 11 blocks on both), and a strength comparison against the baseline through `compare.js` (`compareStoredResults`, `versionRefusalReason`, the baseline reader: export what `ci.js` needs, never copy). Floors per probe class: warn on `scheduled`, block on `release`. A `refused` comparison is informational and routes to `compare --accept`. `merge` is `pr` plus a live preflight when the target needs no secret.
- Fixture baselines come from real `compare --accept` runs over clean copy-workspace runs (AD-8 amended), produced from a neutral temporary location, committed before the next run. They carry the producing machine's paths until Story 1.91 re-accepts them; say so in the reference note, not in a workaround.
- `ci.js` reaches eval-quality only through `engine.js` and `runEngineStage` (string stage names, no `compile`/`seal`/`runScore` identifiers; `test-evaluate-boundaries.js` rules hold). Every new test script joins the `npm test` chain, gets a measured weight in `tools/test-shard-weights.json` and the README chain count moves.
- Exit 13 and the `ci` subcommand are written once and agree in `cli/evaluate.js` (header, `EXIT_CODES`, `buildProgram`, usage), `docs/reference/tea-evaluate-cli.md`, AD-10 (the 10, 11 and 13 rows and a dated amendment) and the Evaluate skill's `references/gaps.md` row 13 (touch that row only; Story 1.61 owns the other rows and the dogfood suite's mutations replace two of them), with `test/test-evaluate-guidance.js`'s assertion on that row updated.

**Never:**

- A verdict, ordering or class computed in TeA from evidence (the engine's exits and the evidence artifact decide); a second taxonomy; a stage exit rewritten or swallowed; `--strict`; a shell.
- A replay that compares a file with itself, copies baseline evidence forward without re-scoring, or reads any file outside `baseline/` as baseline bytes.
- Hand-rolled stale-lock or takeover logic.
- Skill guide edits beyond the `gaps.md` row 13 and what the guide tests require (Story 2.4 owns `references/ci.md` and the rendering in `bmad-testarch-ci`); a flag beyond `--evaluation` and `--tier`; a new exit code beyond 13; edits to Story 1.90's or 1.91's scope (the baseline-digest rule and machine-path scrubbing).

## Implementation Notes

- **Modules.** `cli/lib/evaluate/ci-plan.js` holds the plan reader, the placement rules, AD-10's enforcement table, the severity order and `classify`; `check.js` needs the rules for its `ci-plan` family and `ci.js` requires `check.js`, so they cannot share one file without a cycle. `ci.js` holds the tier runner and every check. `finding-lines.js` is `findingLine` and `escapeUnprintable` lifted out of `cli/evaluate.js`, so `ci` persists each check's output formatted as the CLI prints it. `compare.js` exports the baseline reader (`readBaselineManifest` is new, `baselineTreeFindings`, `readBaselineJson`, `readEvidence`, `walkRegular`, `scoreInvocations`, `probesOf`, `lstatOrNull`), and `CompareOutcome` carries the engine's `relations` per probe so `ci` reads them structurally. `calibration.js` exports `calibrationShortfalls`, which `runCalibration` and `ci` share.
- **Plan decisions the frozen text leaves open.** `enforcement` is `block` or `warn`, and records AD-10's class only (round 1: the action comes from AD-10's table, and `warn` is valid only where AD-10 says warn). `trigger` is a list (a scheduled check also runs on manual dispatch). An `evaluate` check runs by its id and its `command` is the argv a pipeline renders; `ci` checks its lead. A tier holds only the checks placed on it, so the default `merge` and `release` tiers are read as additions a pipeline makes (a merge trigger runs `ci --tier pr` and `ci --tier merge`); AD-10 records it. The same `evaluate` id may sit on several tiers (`twin-run` on `scheduled` and `release`), but not twice on one. `defaultTier` is checked against AD-10's table per id (`DEFAULT_TIERS`: a live preflight defaults to `merge`, `scheduled` or `release`, the rest of the live set to `scheduled` or `release`). A `gate` check counts as deterministic and stays on `pr`, as does every `pr` default; a live check never sits on `pr` (R2-11); `tier` and `placement.tier` must agree. `check` reports the same findings (a `ci-plan` rule family), so a bad plan fails `check` as well as `ci`.
- **Severity and classes.** Final exit order 64, 12, 5, 4, 3, 13, 11, 10, 2, 1, then 0, from the frozen text, recorded in AD-10. An exit outside AD-10's table (a gate's 7, an evaluate check's 1) is class `undocumented exit`, blocks, passes through verbatim and ranks after 1. CONCERNS is read from `contractVerdict` in the evidence artifact; only the `replay` and `gameability` checks read produced evidence for it.
- **Replay determinism, measured.** Over the three fixture baselines the produced `preflight-verdict.json`, each probe's `evidence-artifact.json`, `strength-aggregate.json` and `strength-floors.json` equal the baseline's byte for byte (five files per fixture). The call records of `score` (`score.json` per probe and in total, and `aggregate-strength.json`) hold each engine call's argv with the private staging paths and the invocation id, so they differ by construction; they are the only files the comparison leaves out, and the case asserts that they do differ. Everything `score` wrote is kept under `runs/<invocationId>/replay/scores/`.
- **The clean-control case.** The verdict fixture's control legs (`preflight-control-observe`) are what eval-quality's clean-control check reads, so a changed `exitCode` there makes the engine's own preflight exit 3, which passes through verbatim (class infrastructure or integrity). The frozen row says exit 13 for that edit. Exit 13 is the exit of an observation edit that leaves the engine at its recorded exits: a witness leg's `exitCode` moves the verdict's `fixtureDigest` and nothing else. `test:evaluate-ci` asserts both, with the shim log showing `preflight` and `score` in each; `epics.md` and `test-design-epic-2.md` carry the amendment.
- **Staleness.** The current corpus digest (`buildCorpusIndex`), policy digest (`digestBytes` over `policy/scoring-policy.json`) and compiled contract digest (the `compile` stage over `contract.json`, then `digestArtifact`) are compared with `baseline.json`'s once per invocation. Every check that reads the baseline (`replay`, `gameability`, `oracle-agreement`, `strength-comparison`) warns on `pr`, `merge` and `scheduled` and exits 11 on `release`; the replay itself still runs against the baseline's own snapshot.
- **Live checks.** `twin-run` runs the partition the baseline recorded (everything for the default `both`), because a development run against a `both` baseline is a `refused` comparison; `held-out` runs the held-out partition alone. The twin run asks `run` for the scoring policy's `minimumTrialCount` trials per arm (round 1: `runRunCommand` gained a `trials` option; the held-out run keeps the evaluation's own count). Floors are read from `floorDecisions` in `strength-aggregate.json` (`does-not-meet`), never recomputed; a held-out run has no clean control, so the fixture's `zero-action` floor reads `does-not-meet` with basis `no-eligible-probe`, which is the held-out floor case. `judge-calibration` reads `judge-calibration.json` from the run `twin-run` makes, so it exits 11 on `scheduled` and `release` while a run's own 11 passes through `twin-run` too. `api-conformance` runs the rendered conformance file: exit 0 is 0, exit 1 is 10, a run that cannot finish is 12, an evaluation with no HTTP target is 64.
- **Scratch.** The replay's scratch directory (`tea-evaluate-replay-*`, with an owner file naming the pid and the evaluation folder) is on the invocation's scratch list, removed in `finally` and by the signal handler; a `ci` killed with SIGKILL leaves it and the next `ci` over the same folder removes it once the pid is gone. A stage killed mid-replay is exit 12.
- **Fixtures.** `test/fixtures/evaluate/mutation/evals/verdict-ci` is a copy-workspace clone of the verdict evaluation (so the tests that copy `verdict` keep their first-run behaviour), with `ci/evaluation-ci-plan.json` and `baseline/`; `evaluate-mcp` and `evaluate-api` each gain a plan and a baseline. Each baseline came from a real `run`, `score` and `compare --accept` over a copy of the fixture in a temporary directory outside the repository (`/tmp`), unchanged trial count, `dirty: false`, and carries that machine's paths until a later release re-accepts it; the reference says so. Commit them with this change, since an uncommitted `baseline/` makes the next run in the repository record `dirty: true`. The eight fixtures that predate Story 1.12 gained a `requirements.md`, a `requirements` entry and the matching `sourceSpecDigest`; no probe, mutation, corpus or seal bytes moved, so the corpus indexes and committed probes are unchanged. `test/fixtures/evaluate-promptfoo/evals/summary/corpus-index.json` was already stale at the base commit (`check` over the committed folder exited 10 for it, while `test:evaluate-promptfoo` rebuilds the index in its own copy), so it was regenerated through `tea-evaluate digest`; no probe or mutation byte changed.
- **Test-suite changes.** `test/lib/evaluate-baseline.js` holds what the compare and ci tests share (`copyOf`, `commitAll`, `runAndScore`, `placeBaseline`); `test-evaluate-compare.js` imports it. `test-evaluate-check.js` gains the freshness cases and the walk over every committed evaluation, and its two requirements-statement builders stamp the contract's `sourceSpecDigest`. `test-evaluate-guidance.js` asserts the new `gaps.md` row 13 text; no other row or guide changed.
- **Revert checks, each undone once in a scratch copy of the tree and restored.** Dropping the stdout capture, and writing stderr as stdout, fail the stub `gate` case on the stream; adding `--strict` to the replay's preflight call fails the shim-log case and the static scan; deleting the `placement-reason` rule and the `deterministic-off-pr` rule each makes its case exit 0 instead of 10; swapping two classes in `ENFORCEMENT_TABLE` fails the AD-10 row case; a replay that compares a file with itself (the file comparison made vacuous) and one that never applies exit 13 each fail the flipped-evidence case (exit 0, expected 13); a replay that never re-scores is the same case plus the shim log; removing the stale rule fails the `pr` stale case and the `release` block fails the live-tier case (twin run exit 0, expected 11); an agreement check that ignores `corroboration` passes the flipped-disposition case (exit 0, expected 11); removing the floors fails the held-out case; skipping calibration fails the judge case (exit 0, expected 11); reading a `refused` comparison as a block fails the live-tier case; a gameability check that launches the target (a `run` first) grows the launch marker and fails the gameability case; removing the freshness comparison in `check.js` fails the edited-requirements case (four `test:evaluate-check` checks, exit 0, expected 10).
- **Shard weight 240** for `test:evaluate-ci` is scaled from a local run (about 80 s, against `test:evaluate-check` at 82 s locally and 247 s measured); re-measure in CI. The README's chain count reads 105.

## Design Notes

The replay places the baseline at `runs/<acceptedRun>/` in a scratch folder for the reason Story 2.1 recorded: sealed records name artifacts as `runs/<acceptedRun>/...` and `score` refuses a reference outside the run directory it scores. `score` takes no output location and writes `scores/<newId>/` beside the run it scores, so the replay reads the scratch run's new score subtree and copies the produced files into the real folder's `runs/<invocationId>/replay/`. `preflight` has no standalone replay entry, so the replay calls the engine's `preflight` stage through `runEngineStage` over the baseline's contract, probes and observations. An observation edit moves the produced verdict, which is how the clean-control mutation reaches 13 while `score`'s inputs (contract, verdict, configuration, policy, probe, records, manifest) stay digest-clean.

Severity order for the final exit mirrors `score`'s own (64, 5, 4, 3, 2, 0) and adds the tea-evaluate and gates classes: infrastructure (12) outranks an engine fault because the run cannot be trusted, drift (13) outranks weakness (11) and authoring (10), and a policy violation (1) is lowest. Running every check keeps the evidence bundle complete.
