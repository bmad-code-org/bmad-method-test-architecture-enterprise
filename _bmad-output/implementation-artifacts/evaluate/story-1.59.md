## Intent

**Problem:** A skill or agent target runs an agent CLI through `tea-skill-runner` or its own command. The CLI writes its session and settings state under `HOME`. A confined target is read-only everywhere except its workspace and its call temp, and its environment sets no `HOME`, so the agent's first state write fails and a live skill evaluation has to opt out of confinement to run.

**Approach:** Every confined sandbox gets one private home directory beneath the run's private parent, which the runtime makes and removes, and each independent arm or leg that shares the sandbox starts with it empty. The confined target's `HOME` and the XDG base directories point into it, and the profiles re-grant that one directory inside the withheld private root. Nothing else the target can reach changes.

## Boundaries & Constraints

**Always:** Make the home with `mkdtemp` beneath the run's private parent (`scratch.privateParent`, the `run-<pid>-<random>` directory `makePrivateParent` makes beneath Story 1.58's per-user root `/tmp/tea-evaluate-p<uid>`; prefix `tea-evaluate-target-home-`), once per sandbox; a list with no parent (a unit) keeps the home in `os.tmpdir()`. Every target withholds the root, so the sandbox re-grants only its own home inside it: the Seatbelt allowance comes after the root's denial (the last matching rule wins) and is joined by `file-read-metadata` on the root and each directory down to the home's parent (so a module load, `realpath`, `mkdir -p` and `cd` inside the home resolve, while listing them stays denied), the Bubblewrap bind comes between the root's empty file system and its read-only remount, and the audit keeps the root in `withheld`, lists the home in `granted` and excepts it in `withheldExcept`. Every other home (a stage's, another trial's, another run's) is then unreachable. `targetSandbox` refuses a home inside the workspace or under the evaluation folder. Register the directory in the run's `scratch` list so `removeScratch` removes it, and so a failed trial still removes it. Outside the root a home is granted as the call temp is granted: Seatbelt `file-write*` subpath and Bubblewrap `--bind`, plus the audit's `granted` list. Set `HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` and `XDG_DATA_HOME` for every confined call, overriding any host value a registry entry's `environmentKeys` passes; credentials the agent needs reach it through `environmentKeys` as today. The home persists across the calls of one trial or arm and is empty at the start of each independent arm or leg that shares the sandbox (the next trial, the baseline, mutated and re-pass arms of a qualification, each leg of a `preflight`, each phase of a historical probe); `createProbePort` returns `resetHome()`, which makes a new home beneath the parent, points the sandbox at it (the sandbox reads its home at every wrap, audit and environment call) and removes the old one, and `runArm` and the preflight leg recorder call it before an arm or leg that follows a used one, so a process an earlier arm left running holds a profile that cannot reach the next arm's home. A release moves the old home to a name no sandbox grants before it opens up write bits (without following a link) and removes it, so a read-only directory or a link an agent left cannot keep a home or lead the runtime elsewhere. An opt-out run (`"confinement": false`) keeps today's environment and makes no home. Every profile path goes through `assertProfileSafePath`. A profile change updates `test/fixtures/isolation-primitives/golden.json` with `TEA_UPDATE_ISOLATION_GOLDEN=1 npm run test:isolation-primitives`; read the diff and keep only the added outputs. Cases go in the preflight suite and in `test:evaluate-confinement` (group `confinement`), stay light, and any script added or split refreshes `tools/test-shard-weights.json`. A new `mkdtemp` in `cli/` is listed in `checkPrivateDirectorySources` with its reason. The reference documents the home under `### File-system confinement`, and the Evaluate skill's harness guide shows the confined skill target in a tagged registry example that its guidance test validates. Update `CHANGELOG.md` under `[Unreleased]`. No eval-quality change.

**Never:** a registry field that declares writable paths (nobody needs it; a private home covers the state an agent CLI writes), a grant on the real `HOME`, the project, the evaluation folder or the private root beyond the sandbox's own home, a change to what the profiles grant for the workspace, call temp, report, status or port, evidence, records or digests changed, a new dependency, a Windows change (Windows has no confinement).

## Design Notes

One home per sandbox gives one home per port. State survives the calls of one trial or arm (an agent's session continues) and never crosses to an independent arm or leg, because `runArm` and the preflight leg recorder empty it first. The home sits beneath the run's private parent so that the withheld root, which already covers every stage's and every other run's directories, covers every other home too; the sandbox re-grants exactly its own. A reset keeps the directory, so the profile and vector built for the sandbox stay valid.
